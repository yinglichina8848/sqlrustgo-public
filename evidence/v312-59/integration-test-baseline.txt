### 2. test_ddl_sequential_create_drop_create (PRE-EXISTING)

| Owner | parser-owner |
| Expiry | 2026-09-30 (deferral permitted via disabled-test-registry.md) |
| Evidence (commit) | `cadbc036e2` |

**Test code:**
```rust
fn test_ddl_sequential_create_drop_create() {
    let mut engine = make_engine();
    let _ = engine.execute("CREATE TABLE cycle (id INTEGER)").unwrap(); // <-- FAILS here
    let _ = engine.execute("DROP TABLE cycle").unwrap();
    let result = engine.execute("CREATE TABLE cycle (id INTEGER, name TEXT)");
    assert!(result.is_ok(), "Re-create after drop failed: {:?}", result.err());
    ...
}
```

**Actual behavior:** `Result::unwrap()` on `Err(ParseError("Expected table name"))`.

**Root cause:**
- `crates/parser/src/lexer.rs:501`: `"CYCLE" => Token::Cycle` — lexer always maps "cycle" to the keyword token
- `crates/parser/src/parser.rs:8273-8276`: `parse_create_table` expects `Token::Identifier(name)` for the table name
- "cycle" never reaches the parser as an identifier; CREATE TABLE cycle fails

**Reactivation path:**
Make `CYCLE` a context-aware keyword:
- Lexer: stop unconditionally mapping `CYCLE` to `Token::Cycle` at line 501; instead let the
  parser decide based on context (CREATE TABLE / column position → identifier; CREATE
  SEQUENCE options → keyword)
- Alternative: split into `Token::Cycle` (keyword) and treat unreserved words as identifiers
  via a new `Token::UnreservedIdentifier` enum variant
- Affects 1 file (lexer.rs) and 1 file (parser.rs); regression risk: low since `CYCLE` is only
  used in CREATE SEQUENCE options at parser.rs:2548/2552

Document in `docs/releases/v3.12.0/disabled-test-registry.md` as PRE-EXISTING.
