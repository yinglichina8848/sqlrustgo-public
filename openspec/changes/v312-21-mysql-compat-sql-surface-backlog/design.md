## Design

### 1. Disposition table

A markdown table at `docs/releases/v3.12.0/evidence/mysql_compat/SURFACE_DISPOSITION.md` with columns:

| surface | previous_claim | current_evidence | decision | evidence_hash | owner | expiry |
|---------|---------------|------------------|----------|---------------|-------|--------|

Each row is regenerated by `scripts/gate/check_v312_21_mysql_compat.sh` after running the fixture suite. The script:

- Walks `tests/compat/mysql_v3_12/*.sql`.
- For each, runs the SQL through `MySqlTestClient`, diffs the actual output against `*.out`.
- Sets `decision=PASS` on exact match, `decision=unsupported` on a documented `UNSUPPORTED:` prefix, `decision=deferred` if the fixture's `.out` starts with `DEFERRED:` and a follow-up issue is linked.
- SHA256s the per-row log and the full report.

### 2. Fixture grammar (per `tests/compat/mysql_v3_12/*.sql`)

Minimal MySQL test grammar, line-based:

```
# name: <short name>
# expect: PASS | UNSUPPORTED:<reason> | DEFERRED:<issue-link>
<SQL statements, semicolon-separated>
```

The runner:

1. Strips `# name:` and `# expect:` lines.
2. Connects to an ephemeral server.
3. Sends the SQL as one or more COM_QUERY packets.
4. Compares the captured row output (semicolon-joined, no trailing whitespace) against the expected row set derived from the `*.out` sibling file.
5. Reports PASS/UNSUPPORTED/DEFERRED per file.

### 3. GMP-critical subset (must PASS in v3.12 RC)

These are the surfaces the master issue explicitly names as in-scope:

- `SHOW TABLES` returns the expected list after a series of `CREATE TABLE` and `DROP TABLE` ops.
- `ALTER TABLE ... RENAME TO ...` (V311-13 in v3.11.0; re-verify in v3.12.0).
- `ALTER TABLE ... ADD COLUMN` and `DROP COLUMN` with default value re-evaluation.
- `ALTER TABLE ... MODIFY COLUMN` (V311-13; re-verify with new data types).
- Empty-password auth edge: `MySqlTestClient::connect(user="root", password="")` succeeds if the server config allows it; fails with a clear `ER_ACCESS_DENIED_ERROR` otherwise. The expected `.out` records the auth result.
- Prepared statement round-trip: `COM_STMT_PREPARE` + `EXECUTE` + `CLOSE` for `SELECT ?, ?` — already covered by `binary-prepared-statement-roundtrip`; the new fixture re-asserts at the v3.12.0 release commit.

### 4. Explicit unsupported surfaces (must NOT silently pass)

- `CREATE PROCEDURE`/`CALL` tokens (the parser recognizes the keyword but emits `UNSUPPORTED: stored procedure tokens not implemented`).
- Column-level permissions on columns outside V311-09 (the parser does not yet parse `GRANT ... (col) ...`).
- `WITH ROLLUP`, `WITH CUBE` (the parser recognizes `WITH` but the cube/rollup clause is not in the executor).
- `REPLACE INTO ... AS` with multiple `ON DUPLICATE KEY UPDATE` columns.
- Window-function `RANK()` over `PARTITION BY` with multiple sort keys (only `ROW_NUMBER` is in V312-16's scope).
- Advanced aggregates beyond V311-15/V311-16/V311-17: `STDDEV_POP`, `VAR_POP`, `MEDIAN`, `GROUP_CONCAT` (the executor returns `UNSUPPORTED: aggregate not implemented`).

Each of these is a fixture whose `*.out` literally contains `UNSUPPORTED: ...` — so any future code change that *does* implement one of these will fail the fixture and force an explicit decision update.

### 5. Deferred surfaces (with owner + expiry)

- `TIMESTAMP` type with timezone: deferred to a follow-up issue with owner `<gitea-login>` and expiry `<ISO date>`.
- Connection pool: deferred — server is currently single-threaded per connection; no production pool yet.
- Full `ALTER TABLE ... CHANGE` syntax: deferred to v3.13 (rationale in follow-up issue).

### 6. Release notes boundary

`docs/releases/v3.12.0/RELEASE_NOTES.md` "MySQL compatibility" section is rewritten to:

- Link to `SURFACE_DISPOSITION.md` (the SSOT).
- List only the surfaces with `decision=PASS`.
- List only the surfaces with `decision=unsupported` if a previous version claimed support.
- Deferrals are not mentioned in release notes; they live in the disposition table only.

### 7. Failure mode

If `SURFACE_DISPOSITION.md` is missing, the v3.12 RC sign-off gate (`check_v312_19_release_gates.sh` from issue #3906) refuses to proceed. This is the deliberate link: #3908 produces the disposition, #3906 enforces its presence at sign-off.
