## Context

Issue #4697: the CREATE TABLE column-definition parser doesn't recognise the
SQL-standard `GENERATED ALWAYS AS (expr) [STORED|VIRTUAL]` clause. After the
column name and data type are consumed, the constraint loop fall-through
branches to `DEFAULT <value>` parsing, which expects a literal; the `(expr)`
payload then triggers "Expected SELECT after AS" deeper in the grammar.

## Approach

Three small, contained edits in `crates/parser/src/parser.rs`:

1. **Struct addition** — new `GeneratedColumn { expression, stored }`
   type and a `generated: Option<GeneratedColumn>` field on
   `ColumnDefinition` (with `#[serde(default)]` for round-trip safety).
2. **`#[derive(Default)]` on `ColumnDefinition`** — preserves the existing
   ~20 construction sites without forcing every site to add
   `generated: None,`. ForeignKeyRef already derives Default downstream;
   verify with `cargo check --workspace`.
3. **New arm in `parse_column_definition`'s constraint loop** — when the
   current token is `Identifier("GENERATED")`, consume
   `GENERATED ALWAYS AS (<expr>) [STORED|VIRTUAL]`. The expression is
   captured as the `Display` text of the parsed `Expression` so future
   engine code can render it back to SQL without round-tripping a typed
   tree.

The fix is intentionally parser-only: it accepts the grammar, records the
intent, and does **not** attempt to evaluate or persist the generated value.
Executor work (populate `INSERT` target column, suppress on read for VIRTUAL,
persist for STORED) is a separate v3.13 item.

## Files Changed

- `crates/parser/src/parser.rs` — three edits:
  - `ColumnDefinition` struct: add `Default` derive and `generated` field.
  - New `GeneratedColumn` struct.
  - `parse_column_definition`: declare `let mut generated: Option<
    GeneratedColumn> = None;`, add the GENERATED arm, and include
    `generated` in the returned struct literal.
- `crates/parser/tests/parser_coverage_tests.rs` — tighten the two
  existing generated-column tests (replace `let _ = result;` with
  `assert!(result.is_ok(), ...)`) and add two new tests for VIRTUAL and
  for the multi-column case from the issue body.

## Non-Goals

- `GENERATED ALWAYS AS IDENTITY` storage integration (separately tracked).
- Engine-side evaluation / persistence of generated values.
- `GENERATED BY DEFAULT` variant.
