## 关键决策

### 1. SF=0.1 (不是 SF=0.001)

`tests/tpch_22_queries_wire_test.rs` (Sprint 5 v10 提交) 跑 SF=0.001, 60K
lineitem 会触发的 EAGAIN bug fix (PR-3128) 不能在 501 row scale 上复现. 50x
scale-up 是 canonical TPC-H SF=0.1.

### 2. `set_timeouts()` 必须

Q17 在 SF=0.1 上要 31s. 默认 5s read timeout 杀掉 query, 返回 EOF 而不是结果.
新增 `MySqlTestClient::set_timeouts(300s, 300s)` 让测试可调.

### 3. FP-tolerant cell comparison

Q1/Q3/Q7/Q10/Q15/Q18 是 precision-sensitive. Engine 返回 full IEEE-754
(`146193` vs `146193.0`, `2941.6499999999996` vs `2941.65`). Strict string
match 会假阳性. 用 cell-by-cell + abs<=1e-3 OR rel<=1e-6 FP tolerance.

### 4. Q7/Q8 baseline format fix

原始 baseline 生成脚本有 bug: 把 4 cell 拼成一个 cell 用 `\t` 分隔
(`["GERMANY\tFRANCE\t1993\t868.9800"]`). 这次从 MariaDB 重新生成 4 个
独立 cell. 引擎值是对的, baseline 数据格式错了.
