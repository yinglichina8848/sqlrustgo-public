# WAL HARD GATE Design - v3.8.0

## 1. 目标

在 v3.8.0 结束时，消除所有 non-WAL writable runtime paths，使 WAL 成为系统级强制写入约束（而非可选能力）。

## 2. 当前系统问题

| 写路径 | TX | WAL | 风险 |
|--------|----|-----|------|
| ExecutionEngine → WalStorage | ✅ | ✅ | LOW |
| openclaw_endpoints.rs | ❌ | ⚠️ | HIGH - direct storage calls |
| trigger.rs | ❌ | ⚠️ | HIGH - direct storage calls |
| stored_proc.rs | ❌ | ⚠️ | HIGH - direct storage calls |
| connection_pool.rs | ❌ | ❌ | CRITICAL - uses MemoryStorage |

核心问题：Storage 是 runtime injection（`Arc<RwLock<dyn StorageEngine>>`），编译期无法约束 WAL 行为。

## 3. 解决方案：WAL HARD GATE

### 3.1 扩展 StorageEngine Trait

给 `StorageEngine` trait 增加默认方法：

```rust
pub trait StorageEngine: Send + Sync {
    // ... existing methods ...

    /// Check if this storage engine has WAL enabled
    /// Default: false (no WAL)
    fn is_wal_enabled(&self) -> bool {
        false
    }
}
```

### 3.2 实现 is_wal_enabled()

**MemoryStorage** → `false`（无 WAL）

**WalStorage<T>** → `true`（强制覆盖默认实现）

```rust
// In WalStorage<S>
impl<S: StorageEngine> WalStorage<S> {
    fn is_wal_enabled(&self) -> bool { true }
}
```

### 3.3 WAL Capability Check Gate

在 Path B 各模块构造时强制检查：

```rust
fn new(storage: Arc<RwLock<dyn StorageEngine>>) -> Self {
    assert!(
        storage.read().unwrap().is_wal_enabled(),
        "Storage MUST be WalStorage in production - WAL is mandatory"
    );
    Self { storage }
}
```

### 3.4 connection_pool.rs 强制收敛

当前问题：`PooledSession::new()` 使用 `MemoryStorage::new()`，无 WAL。

v3.8 策略：
- 测试环境：允许 MemoryStorage（现有行为）
- Production 环境：检测到 MemoryStorage 时 log fatal error 或 panic

实现方式：
- 运行时检查：构造时检查 `is_wal_enabled()`，非 WAL 时 panic
- 配合编译期 feature flag `#[cfg(not(test))]` 可选

## 4. 实施范围

| 文件 | 改动 | 类型 |
|------|------|------|
| `crates/storage/src/engine.rs` | 添加 `is_wal_enabled()` 默认方法到 StorageEngine trait | 扩展 trait |
| `crates/storage/src/engine.rs` | MemoryStorage 实现 `is_wal_enabled()` → `false` | 实现 |
| `crates/storage/src/wal_storage.rs` | WalStorage 实现 `is_wal_enabled()` → `true` | 实现 |
| `crates/server/src/openclaw_endpoints.rs` | 构造时 WAL capability 检查 | 硬门 |
| `crates/executor/src/trigger.rs` | 构造时 WAL capability 检查 | 硬门 |
| `crates/executor/src/stored_proc.rs` | 构造时 WAL capability 检查 | 硬门 |
| `crates/server/src/connection_pool.rs` | 构造时 WAL capability 检查，强制 WalStorage | 收敛 |

## 5. 系统结构（收敛后）

```
PATH A (WAL enforced):
ExecutionEngine → UnifiedFacade → WalStorage → Storage
✓ TX enforced + WAL guaranteed

PATH B (WAL hard gate):
HTTP/Trigger/StoredProc → is_wal_enabled() check → ❌ PANIC if false
connection_pool → is_wal_enabled() check → ❌ PANIC if false
```

## 6. v3.8 vs v3.9 分界

- **v3.8**：强制 WAL coverage（运行时断言），不统一写入口
- **v3.9**：引入 TransactionalFacade 作为唯一写入口，统一所有写路径
