### 2.8 v3.9.0 GA (2026-06-25) — 条件豁免

**目标**: 85%

**实际数据**:
| Crate | 覆盖率 | Gap |
|-------|--------|-----|
| types | ~93% | +13pp |
| storage | ~78% | -2pp |
| executor | ~68% | -12pp |
| parser | ~60% | -20pp |
| mysql-server | ~50% | -30pp |
| **平均** | **~67%** | **-18pp** |

- 18pp 差距是有记录的已知差距
- 44 个忽略测试中有 41 个是设计范围或性能测试
- 仅 3 个是真正的 bug (已在 v3.9.0 修复)

**结果**: ⚠️ 条件豁免

## 3. 测量方法演变

### 3.1 工具变化

| 时期 | 工具 | 说明 |
|------|------|------|
| v2.8-v2.9 | tarpaulin | 超时问题 |
| v3.0+ | llvm-cov | 当前使用 |

### 3.2 测量范围变化

| 范围 | 说明 |
|------|------|
| `--lib` | 仅库代码 |
| `--tests` | 库+测试 |
| `--all-features` | 全量 |
| `--lib --tests` | 综合 |

### 3.3 指标定义

| 指标 | 定义 |
|------|------|
| Regions% | 基本块覆盖 (分支/循环) |
| Lines% | 行覆盖率 |
| Functions% | 函数覆盖率 |

## 5. 合理性分析

### 5.1 基于历史的目标建议

| 阶段 | 建议阈值 | 历史依据 |
|------|----------|----------|
| Alpha | 60-70% | v3.6.0 Alpha 81.97%, v3.7.0 Beta 84.99% |
| Beta | 70-75% | v3.7.0 Beta 84.99%, v2.9.0 RC 84.18% |
| RC | 75-80% | 接近历史最高 |
| GA | 75-80% + 基线化 | v3.10.0 先例 |

### 5.2 建议目标

**短期 (v3.11.0)**:
- **Alpha**: ≥65% (使用 --tests)
- **Beta**: ≥70% (使用 --tests)
- **RC**: ≥75% (使用 --tests) 或 建立基线
- **GA**: 条件通过或基线化

**中期 (v3.12.0+)**:
- 目标: ≥80% (per crate average)
- 方法: 统一测量标准

### 5.3 测量标准化建议

1. **统一工具**: llvm-cov
2. **统一范围**: `--tests --all-features`
3. **统一指标**: Lines% (最常用)
4. **基线化**: 每次 GA 建立新基线

---

## 6. 结论

### 6.1 当前要求的问题

1. **85% 阈值历史从未达到**: 最高 84.99% (v3.7.0 Beta)
2. **测量方法不明确**: 不同版本使用不同方法
3. **无统一标准**: STAGE_CONFIG.yaml 无覆盖率阈值定义

### 6.2 建议行动

1. **更新 Issue #3420/#3493**: 设定更现实的目标 (75%)
2. **明确测量方法**: 统一 --tests --all-features
3. **建立基线**: 以 v3.10.0 14.71% 为参考，设定改善目标
4. **文档化**: 在 STAGE_CONFIG.yaml 中明确定义阈值

### 6.3 最终建议

| 当前要求 | 建议修改 | 理由 |
|----------|----------|------|
| #3420: 80% | 75% | 历史最高 84.99%, 平均 70-75% |
| #3493: 85% | 75-80% | 从未达到 85% |
| 统一阈值 | 75% (Beta/RC) | 基于 v2.9.0 RC 成功经验 |
