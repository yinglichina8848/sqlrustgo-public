它们产生同一个后果：**测试的结果取决于跑它的是哪台机器**。

## 3. 改动

### 3.1 新增共享 resolver（#5477 关闭条件第 2 条）

`tests/common/bin_resolver.rs`（新增）—— 定位规则：

1. 显式环境变量（`SQLRUSTGO_BIN` / `SQLITE_BIN` / `SQLRUSTGO_MYSQL_SERVER_BIN`）
2. `CARGO_TARGET_DIR` ⇒ `{debug,release}/<name>` ← **#5477 的要害**
3. `<package-root>/target/{debug,release}/<name>`
4. `PATH`

**任何一步都不得回退到家目录路径。** 找不到时返回 `None`，
调用方必须转成**明确错误**或 **NOT-RUN 披露**，不能转成「通过」。

`tests/common/resolve_bin.sh`（新增）—— shell 侧的同一套规则。

**收敛了 6 处重复实现**（#5477 关闭条件第 2 条）：
`differential_framework.rs`、`tpch_cli_harness.rs`、
`tpch_22_mysql_cli_wire_test.rs`、`l3_canonical_binary.rs`、
`tpch_wire_smoke.rs`、`tpch_wire_smoke_sf.rs`、`e2e_canonical_subprocess.rs`、
`a04_mysql_diff_matrix_test.rs` —— 原本是 **8 份各自独立的实现**。

### 3.2 新增 SF=1 夹具解析（`tests/common/sf1_fixture.rs`）

规则：`TPCH_SF1_DIR` → `TPCH_DATA_DIR` → **缺失**。
缺失时走 NOT-RUN 三态披露（`reason=fixture_missing` /
`reason=profile_mismatch`），**不回退硬编码路径**。

### 3.3 差分对照改为进程内（#5406 的正面修复）

- `tests/common/sqlite_dialect.rs`（新增）：SQLite 方言适配 + 数值感知比较
- `tests/integration/compat/differential_corpus_test.rs`：改为**进程内引擎 + 进程内 `rusqlite`**（`bundled` feature ⇒ CI 不需要额外二进制、不需要网络）
- `tests/compat/bustubx_differential_test.rs`：改为复用共享模块
- `tests/compat/differential_framework.rs`：二进制缺失时给出**明确错误**（点名该设哪个环境变量），而不是空结果

**验证「真的在比对」**：`--nocapture` 下可见 2 条「[SQLite 方言改写]」输出
⇒ oracle 确实执行了，而不是空转。

### 3.4 shell 脚本：`SKIP → exit 0` 改为 NOT-RUN（退出码 77）

`tests/compat/*.sh` 此前在二进制缺失时打印 `SKIP` 并 `exit 0` ——
调用方读成「回归测试通过」，而它其实**一次都没跑**。

现在：打印 `TEST-NOT-RUN: <target> reason=binary_not_found …`，
以**退出码 77**（automake 的 "skipped" 约定）结束 ——
既非 0（不是通过）也非 1（不是失败），三态可区分。

## 4. C6 判据：从字符串启发式改为真不变量

### 4.1 旧判据的问题

旧版 C6 的正则是 `/Users/|/home/[A-Za-z0-9_.-]+/sqlrustgo` ——
只匹配「家目录 → 含 `sqlrustgo` 段」这一种形态。

**实测：改动前树里共 16 处家目录绝对路径，旧正则只抓到 4 处。**
它漏掉了：

- `/home/<u>/tpch_baseline/sf1`（数据夹具）
- `/home/<u>/tpch-dbgen-master/dbgen`（外部工具）
- 检出树不在家目录直接下一级时的**所有**布局
- `tests/**/*.sh` 里的 6 处（旧判据只扫 `*.rs`）

⇒ 旧判据在报告「PASS」的时候，树里还有 **12 处机器相关路径**。
**一个会漏报的判据比没有判据更糟** —— 它给出虚假的安全感。

### 4.2 新判据

> **测试树（`tests/**` 的 `.rs` 与 `.sh`）不得包含以用户家目录为根的绝对路径**
> （`/home/<user>/…` 或 `/Users/<user>/…`）。

理由：**家目录路径按其构造就是机器专属的**，它是「这只在某一台上跑过」
最可靠的标记。而「机器专属性」是**路径**的性质，不是路径所指向的东西
（检出树 / 夹具 / 工具）的性质 —— 所以判据必须针对路径本身。

### 4.3 判别力实测（基线树对照）

### 4.4 豁免机制：显式、可审计

检测器与共享 resolver 本身**必须**携带样本路径才能自证有判别力。
为此提供标记 `c6-allow-home-paths`（必须出现在文件**前 20 行**）：

- 豁免是**显式的**（源码里看得见的标记），不是隐藏的路径白名单
- 豁免是**按文件**的，不是整目录放行
- 每个豁免文件都**列在门禁输出里** ⇒ 「谁豁免了什么」可查

当前豁免清单（2 个，均为判别力所需）：


## 7. 生产代码缺陷：本次**未**修改，另立 issue

修 e2e 时暴露了一个**生产代码**缺陷（不属于本批「测试层」范围）：

`crates/sqlrustgo-cli/src/lib.rs:299-311` 的 `mysql_server_bin()`：

```rust
fn mysql_server_bin() -> String {
    let candidates = [
        "sqlrustgo-mysql-server",
        "./target/debug/sqlrustgo-mysql-server",
        "./target/release/sqlrustgo-mysql-server",
    ];
    for c in candidates {
        if std::path::Path::new(c).exists() || which(c).is_some() {
            return c.to_string();
        }
    }
    "sqlrustgo-mysql-server".to_string()
}
```

它**只看当前工作目录**和 `PATH` ——
既不看**二进制自身所在目录**，也**不看 `CARGO_TARGET_DIR`**。

**实测**：

```
$ cd <target_dir>/debug && ./sqlrustgo
sqlrustgo-mysql-server not found. Run with --help to see available subcommands.
EXIT=1
```

—— 即使 `sqlrustgo` 与 `sqlrustgo-mysql-server` **就在同一目录**。

⇒ `sqlrustgo` wrapper 只有在 **cwd 恰好是构建输出目录的父目录**时才能工作。
这影响 `serve` / `exec` / `repl` 等**全部** server 子命令族。

**本批的处置**：
- 生产代码**未改动**（本批是测试层批次，不单方面改生产语义）
- e2e 用例改为**确定性地**验证两条契约：
  1. 能委托时（把 server 目录加进 `PATH`）⇒ 裸调用委托给 `--help`、退出 0、无 DEPRECATED
  2. 不能委托时（cwd 指向空临时目录 + 清空 `PATH`）⇒ **非零退出**并点名找不到什么
- 生产缺陷**另立 issue** 跟踪

## 7.1 `check_anti_fabrication` 门禁的 7 个错误：既有，与本 PR 无关

该门禁在本 PR 分支上判红（`ERRORS=7`）。逐项归因：

| 错误 | 归因 |
|---|---|
| `V312-24: target/release/sqlancer not built` | 既有 —— 仓库未 vendor `sqlancer` 源码（与 #5387 同族的「二进制来源缺失」） |
| `V312-24 artifacts check: 2 failure(s)` | 同上 |
| `NEW: no_namespace_db_refusal_5266` | **既有** —— 见下方实测 |
| `NEW: sqlrustgo-storage` | 同上（主 workspace crate 编译失败的连带传播） |
| 其余 3 项 | 门禁自身的 report / 身份检查项 |

### 实测：基线 worktree 上错误完全相同

在**基线 worktree**（`wt-v410-b7base`，HEAD = `009bb985ee`，**零改动**）上：

```console
$ cargo test -p sqlrustgo-storage --no-run --test no_namespace_db_refusal_5266
error[E0432]: unresolved import `sqlrustgo_storage::BinaryTableStorageV2`
25 | use sqlrustgo_storage::{BinaryTableStorage, BinaryTableStorageV2};
   |                                             ^^^^^^^^^^^^^^^^^^^^ no `BinaryTableStorageV2` in the root
93 | pub use binary_storage_v2::BinaryTableStorageV2;
   |                            ^^^^^^^^^^^^^^^^^^^^ the item is gated behind the `bin_storage_default` feature
error: could not compile `sqlrustgo-storage` (test "no_namespace_db_refusal_5266") due to 1 previous error
```

⇒ **错误文本与本 PR 分支上逐字相同**。

根因：`BinaryTableStorageV2` 被 `#[cfg(feature = "bin_storage_default")]` gate 住，
而门禁的 `cargo test --workspace --no-run` **未开该 feature** ⇒ 编译失败。

⇒ 这是**既有的 feature-gate 缺口**，与本 PR 无关：**本 PR 未改动任何
`crates/` 下的文件**（见 §8 的完整改动清单）。
按治理原则「基准对照是判定『是否本 PR 引入』的唯一硬证据」，
此项归因为**既有失败**，不计入本 PR。
