## 0. 一句话

`crates/vector/src/simd_explicit.rs` 的 `cosine_similarity_simd` 用
**「向量到自身的欧氏距离」**当范长 —— 那个值恒为 0 ⇒ 相似度**恒为 0.0** ⇒
cosine 度量下的相关性排序**完全不携带任何信息**。

---

## 1. 缺陷本体

```rust
pub fn cosine_similarity_simd(a: &[f32], b: &[f32]) -> f32 {
    let dot = dot_product_simd(a, b);
    let norm_a = euclidean_distance_simd(a, a).sqrt();   // 恒为 0
    let norm_b = euclidean_distance_simd(b, b).sqrt();   // 恒为 0

    if norm_a == 0.0 || norm_b == 0.0 {
        return 0.0;                                     // 恒走这一支
    }

    dot / (norm_a * norm_b)                             // 永远到不了
}
```

`euclidean_distance_simd(a, a)` 是**向量到自身的距离**，恒为 0 ⇒
`norm_a` / `norm_b` 恒为 0 ⇒ 函数恒返回 `0.0`。

**与平台无关**：该函数的标量 fallback 与 AVX2 路径算的是同一个量，
两边都是 0 ⇒ 在任何架构上都是坏的。

### 1.1 影响面（比 Issue 描述的更大）

| 调用点 | 后果 |
|---|---|
| `crates/vector/src/flat.rs:81` | `FlatIndex::search` 的 cosine 分支 ⇒ **排序完全失效** |
| `crates/vector/src/hnsw.rs:133` | `HnswIndex` 的 cosine 分支 ⇒ **图构建与搜索都失效**（Issue 未提及） |
| `crates/vector/src/simd_explicit.rs:217` | `compute_similarity_simd` 的 cosine 分支 |
| `crates/vector/src/simd_explicit.rs:278` | `batch_cosine_distance_simd` ⇒ `FlatIndex` 走的正是它 |
| `crates/vector/src/lib.rs:75` | 作为**公共 API** 导出 ⇒ 仓外调用者也受影响 |

### 1.2 为什么它能长期存在：同一条规则被复制了四份

仓内共有四个 cosine 实现：

| 位置 | 范长怎么算 | 状态 |
|---|---|---|
| `src/metrics.rs:43` | `a.iter().map(\|x\| x * x).sum().sqrt()` | 正确 |
| `src/gpu_accel.rs:109` | 同上 | 正确 |
| `src/parallel_knn.rs:26` | `dot_product(a, a).sqrt()` | 正确（**且注释里写着「不是到自身的距离」**） |
| `src/simd_explicit.rs:143` | `euclidean_distance_simd(a, a).sqrt()` | **坏** |

`parallel_knn.rs` 的注释本身就是证据 —— 作者当时知道这个陷阱：

```rust
// Norm is sqrt(dot_product), not euclidean_distance to self (which is always 0)
```

**同一条规则，四份实现，其中一份写错，而且没有任何守卫能发现它** ——
因为没有任何测试同时用到两份实现。

⇒ 这正是「一个规则只有一份实现」这条原则要防的事。

## 2. 修法：把规则收成一处

新增 `metrics::l2_norm`（范长 = 欧氏长度），**四处 cosine 实现全部调用它**：

```rust
/// #5384: this rule used to be spelled inline in four places, and the SIMD
/// copy spelled it **wrong** …
pub fn l2_norm(v: &[f32]) -> f32 {
    v.iter().map(|x| x * x).sum::<f32>().sqrt()
}
```

改动清单：

| 文件 | 改动 |
|---|---|
| `src/metrics.rs` | 新增 `l2_norm`；`cosine_similarity` 改用它 |
| `src/simd_explicit.rs` | `cosine_similarity_simd` 改用它（**核心修复**）；新增 `batch_cosine_similarity_simd` |
| `src/parallel_knn.rs` | `cosine_similarity` 改用它 |
| `src/gpu_accel.rs` | `cosine_similarity` 改用它 |

另外，SIMD 版与 parallel-knn 版补上了**长度/空检查**（与标量版一致），
长度不匹配时返回 `0.0` 而不是越界读。

### 2.1 连带修复：`FlatIndex` 的 cosine 分支**符号反了**

Issue 只说「排序失效」，但真正的原因有**两层**：

1. 相似度恒为 0（已修）；
2. `flat.rs` 的 cosine 分支返回的是**距离**（`1 - 相似度`），
   而所有条目按**降序**（越大越近）排序 ⇒ **方向是反的**。

即使把相似度修好，第 2 层仍会让**最不相似的**排在最前。

判据来自 `traits.rs` 的契约与 `flat.rs` 自带的测试：

```rust
/// Similarity score (higher is better for cosine/dot, lower is better for distance)
pub struct IndexEntry { pub id: u64, pub score: f32 }
```

```rust
// crates/vector/src/flat.rs 的既有测试
let mut index = FlatIndex::new(DistanceMetric::Cosine);
…
let results = index.search(&[1.0, 0.0, 0.0], 2).unwrap();
assert_eq!(results[0].id, 1);
assert!((results[0].score - 1.0).abs() < 0.001);   // 期望 score 是**相似度**
```

⇒ 修法：`flat.rs` 的 cosine 分支改用 `batch_cosine_similarity_simd`。

**这个既有测试此前是「假绿」**：坏实现下所有 score 恒为 `1 - 0 = 1.0`
⇒ `score ≈ 1.0` 恰好成立；`results[0].id == 1` 则靠插入顺序侥幸成立。
⇒ 本批的新测试把这件事变成了**真的**断言。

### 2.2 一致性（非修 bug）：`HnswIndex` 的 cosine 分值

`HnswIndex` 内部用**距离**做图构建与搜索（这是对的），返回时统一转成
「越大越好」。修好相似度之后，cosine 的返回值是 `-(1 - 相似度) = 相似度 - 1`
⇒ **单调性正确**（排序没问题），但**分值语义**与 `FlatIndex` 不一致
（同一个 metric，flat 给 1.0、hnsw 给 0.0 表示「完全相同」）。

⇒ 已统一为**相似度**：

```rust
let score = match self.metric {
    DistanceMetric::Cosine => 1.0 - dist,
    _ => -dist,
};
```

`HnswIndex` 此前没有任何对 `score` 值的断言 ⇒ 该改动不破坏既有测试。

| `mismatched_lengths_score_zero_instead_of_reading_out_of_bounds` | 恒成立（长度检查是本批**新加**的，坏实现里也保留） |

## 5. 未达成 / 未验证项

1. **CI 上的实测结果待补** —— 本批的测试全部在本地（macOS / aarch64）跑过；
   CI 在 Linux / x86_64 上会走 AVX2 路径 ⇒ 实测结果待补。
2. **`ivf.rs` / `ivfpq.rs` / `parallel_knn.rs` / `sql_vector_hybrid.rs` 的
   `score` 语义未统一** —— 它们各有各的约定（`ivfpq` 用 `-score`，
   `parallel_knn` 直接用 `score`）。本批**没有**改动它们：cosine 的
   **相似度计算**在那几处本来就是对的（它们不经过
   `cosine_similarity_simd`），改 score 符号属于**扩大范围**，应当单独评估。
3. **仓外的调用者**若依赖了「cosine 的 score 是距离」这一（错的）旧行为，
   本批会把它们改成「相似度」⇒ 属于**行为变更**，需要在 release notes 里点名。
