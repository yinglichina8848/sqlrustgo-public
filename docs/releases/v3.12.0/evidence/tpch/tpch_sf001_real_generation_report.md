## 3. Reproduction Steps

The committed reproducer is `scripts/tpch/setup_sf1.sh`:

```bash
# 1. Build dbgen (one-time)
cd ~/tpch-dbgen-master
make        # produces ./dbgen

# 2. Run the setup script (writes to tests/data/tpch-sf001-real/)
cd /home/openclaw/workspace/dev/sqlrustgo
bash scripts/tpch/setup_sf1.sh
```

`scripts/tpch/setup_sf1.sh` invokes `dbgen -s 1 -f` and copies the 8
resulting `.tbl` files into `tests/data/tpch-sf001-real/`. Total wall-clock
on a modern x86_64 box is ~3 seconds for SF=1.

For SF=10 the sibling script `scripts/tpch/setup_sf10.sh` (target
`/tmp/tpch-sf10`) is used; for SF=0.01 the script
`scripts/tpch/setup_sf00001.sh` writes to `tests/data/tpch-sf001/`.

## 4. Git Tracking Decision

Per the project-wide constraint in `AGENTS.md` and the existing `.gitignore`
at lines 65–73, **none of the `.tbl` files are tracked**. The
`.gitignore` already excludes:

```gitignore
tests/data/tpch-sf001-real/*.tbl

```

This commit extends the exclusion to also cover the runtime side-effects
emitted by the bulk-load harness into the same directory during the
investigation that produced commit `1e218434a0` (table-metadata `.json`
dumps and the WAL `.wal` file):

```gitignore

tests/data/tpch-sf001-real/*.json
tests/data/tpch-sf001-real/*.wal
```

This keeps the directory present on disk for local investigation and
re-running `bulk_load_sf1.sh`-style harnesses, but prevents any of the
~1.1 GB of `.tbl` source data, the ~6 MB of `.json` runtime dumps, or
the ~2 MB `.wal` runtime artifact from being committed.
