## 2. 真正根因 (Root Cause Analysis)

### 2.1 Z6G4 reboot 本身 (无确切证据)

- LAN 192.168.0.0/24 全挂 (~30+ 分钟) 包括 252 + 250
- 物理 reboot (最可能: power 波动, kernel panic, 或 OOM)
- `dmesg` 留不下 (重启清空), 无法 trace
- 不是 gitea 自身 bug

### 2.2 Gitea 启动失败链

1. `devstack-gitea-1` 在 reboot 时 crash (signal 11 或断电)
2. Docker restart policy 触发 restart
3. **但** gitea container 重新连 `devstack_devstack` network 时拿到**新 IP** (postgres IP 也变)
4. `app.ini` 写死 `HOST = 172.21.0.2:5432` (旧 IP)
5. Gitea 连不上 postgres, 启动失败 (10 次重试)
6. **手动修复**: 更新 `app.ini` 到新 IP

### 2.3 持续 Runner 500 error (非 Gitea 健康问题)

- 5 个 `devstack-runner-*` 容器每分钟 call `RunnerService/Declare`
- Server returns 500 (Unregistered Runner) — gitea **正确**响应 (token expired)
- Runners 进入 restart loop, 每次 restart 1 分钟
- **不影响** gitea web functionality (HTTP 200)
- 但 log file 持续 grow

### 2.4 devstack-gitea-1-backup 启动冲突

- `devstack-gitea-1-backup` (backup container) 与 `devstack-gitea-1` 都想 bind port 222
- backup container Exited (128) 16 min ago
- 现 active gitea bind 222, backup 没起 — 实际**OK**, 不影响功能


#### B. 添加 Gitea 启动 watchdog

```bash
# /opt/devstack/watchdog-gitea.sh (cron every 5 min)
#!/bin/bash
if ! curl -sf -o /dev/null --max-time 10 http://localhost:3000/api/v1/version; then
    docker restart devstack-gitea-1
    echo "$(date): gitea restarted" >> /var/log/gitea-watchdog.log
fi
```

Crontab:
```cron
*/5 * * * * /opt/devstack/watchdog-gitea.sh
```

#### C. 备份 Gitea app.ini 到 host (避免 container restart 丢失)

```bash
# /opt/devstack/backup-gitea-config.sh (cron daily)
#!/bin/bash
docker exec devstack-gitea-1 cat /data/gitea/conf/app.ini > /opt/backups/gitea-app.ini-$(date +%Y%m%d)
```
