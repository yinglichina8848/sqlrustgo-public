# Gate Results — Per-Stage Run Report

> **Purpose**: Single-file record of one stage gate run, auto-generated
> by `check_stage.sh --json` + a short human narrative.
> **Per version**: `docs/releases/vX.Y.Z/gate-results/`
> **Naming**: `YYYY-MM-DD-<STAGE>-<MODE>.{json,md}` (e.g. `2026-07-01-RC8-dry-run.json`)
> **Replaces**: ad-hoc "gate pass/fail" sections in per-version plans.
> **Ref**: `STAGE_CONFIG.yaml` (framework) + `STAGE.yaml` (per-version state)

---

## Template

Each gate result file has 2 parts:

1. **`<name>.json`** — machine-readable, generated by `check_stage.sh --json`
2. **`<name>.md`** — human narrative (this template)

### Markdown template body

```markdown

## Cross-references
```

## How to generate

```bash
# 1. Auto-generate JSON
bash scripts/gate/check_stage.sh --dry-run --json 2>/dev/null \
  | python3 -c "
import json, sys
text = sys.stdin.read()
start = text.find('{'); end = text.rfind('}')
if start >= 0 and end > start:
    d = json.loads(text[start:end+1])
    print(json.dumps(d, indent=2, ensure_ascii=False))
" > docs/releases/v3.9.0/gate-results/2026-07-01-RC8-dry-run.json

# 2. Write narrative (this template) as a .md file
# 3. Commit to release branch

# For an actual run (not dry-run):
bash scripts/gate/check_stage.sh > docs/releases/v3.9.0/gate-results/2026-XX-XX-RC8-actual.log 2>&1
bash scripts/gate/check_stage.sh --json 2>/dev/null \
  | python3 -c "..." \
  > docs/releases/v3.9.0/gate-results/2026-XX-XX-RC8-actual.json
```

## Index convention

- `gate-results/` is the canonical "when was this version at which stage and what was the result" record
- INDEX.md or STAGE.yaml can reference the most recent result file
- Older results are NOT deleted (audit trail)

## Examples (templates only)

- `2026-07-01-RC8-dry-run.json` + `2026-07-01-RC8-dry-run.md` (this session)
- `2026-XX-XX-RC8-actual.json` + `2026-XX-XX-RC8-actual.md` (when running for real)
- `2026-XX-XX-GA-pre-cut.json` + `2026-XX-XX-GA-pre-cut.md` (before GA cut)

## Anti-patterns (what NOT to do)

- ❌ Don't write "本版本的 GA 阶段需要跑 check_g13_stability.sh" in V390_TEST_PLAN.md — that's now in STAGE_CONFIG.yaml#gate_definitions
- ❌ Don't write "G13 阻塞" in CHANGELOG.md — that's in STAGE.yaml#blocker_issues
- ❌ Don't write "Stage 转换: BETA → RC" prose — that's in STAGE.yaml#stage_history
- ❌ Don't re-derive G-lists in per-version docs — STAGE_CONFIG.yaml#gate_definitions is the SSOT
